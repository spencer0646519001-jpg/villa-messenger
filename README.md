# homestay-night-concierge

FastAPI-based homestay inquiry assistant for LINE. It receives LINE webhook
messages, parses booking intent, builds deterministic preliminary quotes,
optionally checks Google Calendar availability, and notifies owners when manual
attention is needed.

This repository is public. Do not commit real tokens, calendar IDs, LINE user
IDs, host details, private tenant data, or operational secrets.

## What It Does

- Receives LINE text-message webhooks, verifies the LINE signature, resolves the
  channel to a tenant, and acknowledges valid requests with `200 OK`.
- Runs webhook processing in FastAPI `BackgroundTasks` after the response is
  sent. This is same-process background work, not a durable queue.
- Persists inbound messages, inquiry decisions, dedupe records, and multi-turn
  conversation state in SQLite.
- Accumulates booking slots across turns, including dates, guest counts, room
  count, and pets.
- Produces preliminary quotes through rule-based pricing logic and tenant
  configuration. Pricing is not generated by the LLM.
- Resolves bare dates (`2/6-2/8`, `明年 2/6`) against the message's own
  timestamp in tenant-local time, so a month/day with no year means the next
  time it occurs rather than the current calendar year.
- Fetches the Taiwan government working-day calendar one year at a time, caches
  it in SQLite, and derives national-holiday and spring-festival date sets from
  it. **If the calendar for a year the stay touches is unavailable, the system
  does not quote** -- it replies with the staff-confirmation line and notifies
  the owner. Missing calendar data must never be priced as "that year has no
  holidays".
- Routes supported FAQ topics through deterministic matchers and reply
  templates.
- Optionally checks Google Calendar before sending a quote. Blocked dates are
  handled as unavailable and can notify owners; calendar errors fall back to a
  cautious quote-and-notify path.
- Sends LINE replies to guests and LINE push notifications to owners when the
  decision requires it.

## Design Boundary

The LLM layer is deliberately narrow. It may help with fuzzy date translation
and booking-intent judgment, then return structured parse fields. It does not
decide prices, availability, state transitions, FAQ routing, owner notifications,
or customer-visible wording.

All customer replies come from local templates and deterministic services. If an
LLM call times out, returns invalid JSON, raises a provider error, or exhausts
the configured fallback provider, the system keeps the rule-parser result and
continues without LLM output.

The system must not guarantee availability, confirm bookings, reserve rooms, or
process payments. All quotes are preliminary and require staff confirmation.

## Tech Stack

- FastAPI + Uvicorn
- SQLite
- LINE Messaging API
- OpenRouter-compatible LLM providers
- Google Calendar API
- pytest

## Project Layout

- `app/api/` - FastAPI routes and request dependencies.
- `app/domain/` - pure parsing, pricing, availability, FAQ, and reply rules.
- `app/services/` - orchestration for inquiries, conversation state, operation
  mode, availability, and persistence.
- `app/adapters/` and `app/clients/` - LINE, LLM, and Google API boundaries.
- `app/repositories/` - SQLite schema and repository layer.
- `data/tenants/<tenant_slug>/config.json` - tenant configuration such as
  pricing, room policy, stay policy, FAQ data, and optional calendar settings.
- `tests/` - pytest coverage for webhook, parsing, pricing, state, LLM fallback,
  availability, repositories, and API behavior.

## Local Development

Create and activate a virtual environment:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Install dependencies:

```powershell
pip install -r requirements.txt
```

Create local configuration from the example file:

```powershell
Copy-Item .env.example .env
```

Fill `.env` with your own local values only. `.env` is ignored by git and must
not be committed.

Run the app:

```powershell
uvicorn app.main:app --reload --port 8000
```

Run the test suite:

```powershell
python -m pytest
```

For local LINE webhook testing, initialize the SQLite schema and seed local
tenant/channel data with the helper scripts under `scripts/`, using placeholder
IDs from your own LINE test channel. Generated SQLite database files are ignored
by git.

## Environment Variables

Use `.env.example` as the public template. Values below are intentionally
omitted; set them only in your private `.env` or deployment environment.

| Variable | Required? | Purpose |
| --- | --- | --- |
| `LINE_TEST_CHANNEL_ID` | Local/test metadata | Test LINE channel identifier reference. |
| `LINE_TEST_CHANNEL_SECRET` | Required for LINE webhook verification | Secret used to verify `X-Line-Signature` when the tenant channel points to this env var. |
| `LINE_TEST_CHANNEL_ACCESS_TOKEN` | Required for LINE replies/pushes | Channel access token used by the LINE send client. If missing, receiving can still succeed but outbound sends are skipped. |
| `LINE_TEST_OWNER_USER_ID` | Optional fallback | Fallback owner recipient when no active owner rows are configured in SQLite. Use a placeholder in examples. |
| `OPENROUTER_API_KEY` | Required only when LLM is enabled with a real provider | API key for OpenRouter-compatible model calls. |
| `LLM_ENABLED` | Optional, default off in runtime factory | Enables LLM-assisted parsing. When disabled, parsing stays rule-based. |
| `LLM_PROVIDER` | Required when LLM is enabled | Primary provider name supported by the adapter layer. |
| `LLM_PRIMARY_MODEL` | Required when LLM is enabled | Primary model ID passed to the OpenRouter-compatible client. |
| `LLM_TIMEOUT_SECONDS` | Optional | Timeout for the primary LLM call. |
| `LLM_FALLBACK_ENABLED` | Optional, default off | Enables provider-level fallback before returning to rule-based parsing. |
| `LLM_FALLBACK_PROVIDER` | Required only when fallback is enabled | Fallback provider name. |
| `LLM_FALLBACK_MODEL` | Required only when fallback is enabled | Fallback model ID. |
| `LLM_FALLBACK_TIMEOUT_SECONDS` | Optional | Timeout for the fallback LLM call. |
| `GOOGLE_CALENDAR_AVAILABILITY_ENABLED` | Optional, default off | Enables live Google Calendar availability checks before quote replies. |
| `ZHEN123_CALENDAR_ID` | Required only when calendar checks are enabled for the configured tenant | Tenant calendar ID env var referenced by tenant config. Do not publish the real value. |
| `GOOGLE_CALENDAR_CREDENTIALS_PATH` | Required only when calendar checks are enabled | Path to a local Google service-account JSON file, for example `secrets/service-account.json`. |

## Secrets And Configuration

- `.env` is for private local values and is ignored by git.
- `secrets/` is ignored by git and is the expected place for local service
  account JSON files such as `secrets/service-account.json`.
- Deployment environments must provide their own environment variables and
  secret files outside the repository.
- Tenant configuration may reference environment variable names, but real
  calendar IDs, LINE IDs, owner IDs, and credentials must stay outside tracked
  files.

## Deployment Notes

The LINE webhook handler acknowledges valid requests first, then runs processing
in FastAPI `BackgroundTasks`. Configure the process manager with enough graceful
shutdown time for same-process background tasks to finish. For production-grade
durability, replace this with an external queue before relying on guaranteed
delivery.

Schema changes are not applied on startup. Run `init_db()` once before starting
a new version whose `schema.sql` has changed; see `docs/deployment.md`.

The holiday calendar is fetched over HTTPS from a public CDN
(`cdn.jsdelivr.net`) and cached per year in SQLite. The deployment needs
outbound HTTPS to that host. If it is unreachable, quoting degrades safely
rather than incorrectly: affected stays are handed to staff instead of being
priced without holiday data. Startup warms the current and next year in the
background.

Health endpoints:

- `GET /health`
- `GET /health/tenant/{tenant_slug}`
